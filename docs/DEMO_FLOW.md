## Scenario 1 — Engineering -> Budget -> Mayor transaction

1. Enter the **Department Head** workspace and choose **Municipal Engineering Office**.
2. Open **My Work** and show Engineering-specific work.
3. Choose **New Transaction**.
4. Select transaction type **Funding request**.
5. Use subject: **Road Rehabilitation Funding Request — Prototype Day**.
6. Add a short description and select **High** priority.
7. Choose **Municipal Budget Office** as the receiving office.
8. Optionally attach a small non-sensitive supporting file if attachment proof is desired.
9. Route the transaction.

Important:

The transaction reference is generated by the backend as:

`TAL-<year>-<six-digit id>`

Do not attempt to type or promise a fixed reference such as `TAL-2026-DEMO-001`.

10. Record the generated reference shown after creation.
11. Switch to the **Department Head -> Municipal Budget Office** workspace.
12. Find/open the generated transaction.
13. Perform the available Budget review/forward action required by the current workflow and route it to the Mayor's Office.
14. Switch to **Municipal Executive**.
15. Open **Mayor's Office / For Decision**.
16. Open the same generated transaction.
17. Review the routing history and prior remarks.
18. Approve it.
19. Switch back to Engineering.
20. Open the same transaction and show the terminal approved state.
21. Show the append-only routing/event history.

Prototype-day success:

- one real database transaction crosses offices;
- responsibility changes are visible;
- Mayor decision is authoritative;
- Engineering sees the final state;
- event history remains visible.

## Scenario 2 — Memorandum publication and acknowledgement

1. Enter **Municipal Executive**.
2. Open **Memoranda** and choose **Publish memorandum**.
3. Set a unique memo number. `MEMO-2026-DEMO-001` may be used if it does not already exist.
4. Use a short prototype-day title/body.
5. Audience: **All Employees**.
6. Keep **Require employee acknowledgement** enabled.
7. Publish and deliver.
8. Record the actual memo number used.
9. Switch to **Employee**.
10. Open the new memorandum.
11. Acknowledge it.
12. Switch back to **Municipal Executive**.
13. Open the memorandum and show delivered/viewed/acknowledged statistics.

Do not reuse a memo number that already exists; memo numbers are unique.

## Scenario 3 — Legislative record search

1. Enter **Legislative Office** or another authorized internal workspace with legislative-read access.
2. Open **Legislative**.
3. Search for **waste**.
4. Show the seeded ordinance concerning solid-waste policy.
5. Search for **infrastructure** or **road**.
6. Show the seeded road-rehabilitation resolution.
7. Open a result and show record number, title, date, status, issuing body, summary, and keywords/metadata available in the current UI.

## Scenario 4 — Employee leave -> HR approval

1. Enter **Employee**.
2. Open the HR/employee-services surface.
3. Show the employee's current leave balances.
4. Submit a small valid leave request that does not exceed the displayed balance.
5. Record the request details.
6. Switch to **Human Resources**.
7. Open **HR Administration**.
8. Find the pending request.
9. Approve it.
10. Switch back to **Employee**.
11. Show the approved request and updated balance/ledger-visible outcome.

Use dates/units accepted by the current form. Do not improvise a request that exceeds the available balance.
