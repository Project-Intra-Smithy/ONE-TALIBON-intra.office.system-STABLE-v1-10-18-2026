# 9. Engineering inference

Engineering inference is permitted for implementation mechanics when consistent with higher authority.

Examples:

- use a read-model/projection for Unified My Work rather than merging source models;
- use a minimal cross-domain reference convention;
- require bounded queries/pagination;
- use contract-release gates to unlock frontend work.

Inference must be labeled when it introduces a design not explicitly required by business authority.

Inference may never be used to manufacture municipal process truth.

# 10. Conflict rule

When two sources conflict:

1. stop;
2. identify the truth class in conflict — software / architecture / business / production;
3. apply the authority hierarchy for that class;
4. record a clarification/decision;
5. do not silently reconcile incompatible facts.

Allowed states:

`CONFIRMED / SUPERSEDED / INPUT REQUIRED / CONFLICT / UNKNOWN`
